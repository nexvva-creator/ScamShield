# ClearBeacon

A privacy-first, mobile-friendly anti-scam decision-support MVP. The app checks pasted URLs and messages, explains local-rule signals, accepts private scam reports, and provides token-protected moderation.

> ClearBeacon is an independent educational project, not a government service or a security guarantee. ClearBeacon is a provisional name and has not been cleared for public use. Do not imply government affiliation; complete name, domain, and trademark clearance before release.

## Run locally

Requires Python 3.10+; the app uses only the Python standard library.

```powershell
cd "F:\Download File\Custom Website Zip\scamshield"
python tools\create_reviewer.py
# Copy the printed JSON object into this environment variable (do not commit it):
$env:SCAMSHIELD_REVIEWERS = '{"reviewer-name":{"salt":"...","password_hash":"...","role":"admin"}}'
python server.py
```

Open <http://127.0.0.1:8000>. The reviewer sign-in is at <http://127.0.0.1:8000/admin>; use the username and password entered into `tools\create_reviewer.py`. The printed PBKDF2 credential JSON is held in `SCAMSHIELD_REVIEWERS`; it contains a password hash, not the password. The account-creation tool can optionally provision TOTP authenticator MFA; when enabled, provide the six-digit code at sign-in. Failed login throttles persist in SQLite, and reused TOTP codes are rejected. Roles are `admin` and `reviewer`; a reviewer can review but cannot assign, manage feeds, revoke sessions, or use bulk actions. Sessions expire after 30 minutes and administrators can revoke every session for a named account. Removing or changing account credentials in `SCAMSHIELD_REVIEWERS` and restarting the server disables that account and invalidates its sessions. An explicitly configured legacy `SCAMSHIELD_ADMIN_TOKEN` remains supported for local migration; it does not have MFA or named-session controls, so prefer named reviewer accounts. Stop with Ctrl+C. The default listener is loopback-only. Reports are stored in `data\scamshield.sqlite3`; pasted checks are analyzed in memory and not retained. Set `SCAMSHIELD_DB` to use a different SQLite path. For a classroom demo only, set `SCAMSHIELD_HOST` or `SCAMSHIELD_PORT` to override the bind address or port. Do not expose this development server to the public internet.

Legacy `SCAMSHIELD_*` environment variables, the `scamshield` Python package, and the SQLite filename remain unchanged for compatibility with existing local configuration and data.

## What works in this MVP

- URL checks: validates HTTP(S) inputs, blocks local/private/reserved IP addresses, and highlights explainable lexical signals. The server never opens or fetches submitted URLs.
- Recent checks: keeps up to ten result summaries in browser storage on the user's device. It does not save the original URL or message and does not upload history. Users can reopen a result or clear the local history; saved evidence remains in the language used for that check.
- Safety response planner: gives practical next steps for shared passwords or codes, payments, suspicious links, and remote-access apps. It does not ask users to disclose the incident details.
- Official-help directory: links to official reporting or cyber-safety resources in the United States, Canada, India, France, Bangladesh, the United Kingdom, Australia, Spain, Mexico, Pakistan, and the United Arab Emirates. The directory is a starting point, not a complete list of local authorities; links open external government or public-service websites, and urgent financial losses should be reported to the user's bank promptly. Links are references, not endorsements; the current application warns users to confirm the address and remit before sharing information.
- Scam-awareness quiz: three short scenarios test safer choices in a single browser session. Answers and scores are not sent or saved.
- Language switching: the interface, guide library, check results, explanations, actions, and disclaimer support English (`en`), Spanish (`es`), French (`fr`), Hindi (`hi`), Arabic (`ar`), and Bengali (`bn`). The browser's preferred supported language is selected on first visit; a manual choice is saved in that browser. Arabic uses a right-to-left layout.
- Bangla: Bengali (`bn`) UI labels, locally analyzed scam phrases, Bangla safety-guide steps, response-planner examples, quiz questions, and Bangladesh official-help link are included. Some long-form copy remains English and needs native-speaker review before wider release.
- Message checks: local illustrative phrase rules cover OTP/PIN requests, urgency, advance fees, unexpected prizes, job offers, identity-data requests, link-pushing, and unrealistic returns. English has broader phrase coverage; all other languages include representative phrases, not comprehensive national-language detection. Extracted link hostnames are never visited.
- Safety library: thirteen searchable, category-filtered guides cover account codes, urgent payments, job fees, unfamiliar shops, links, prizes, recovery, romance, investments, tech-support, delivery, and impersonation. Guide titles and summaries are available in English, Bangla, Spanish, French, Hindi, and Arabic; some long-form copy remains English or Bangla.
- Email header review: locally checks visible `From`, `Reply-To`, `Return-Path`, and pasted SPF/DKIM/DMARC results. Header text is only processed in memory; it does not verify the message cryptographically or contact a mail provider.
- Context checks: local phrase checks and printable safety checklists for job offers, marketplace transactions, and payment requests; caller guidance explains spoofable caller ID and does not identify or score phone numbers.
- Organization comparison: checks entered hosts against a small static official-help reference directory without fetching the entered address. The directory includes source and catalog date, but is not live-verified and is not an endorsement.
- Structured reports: optional contact channel, incident date, language, and evidence notes are collected to make reports easier to triage. Reporters can export their own report and appeal data as JSON or CSV, or print/save a PDF in their browser, using the private reference.
- Privacy-protective trend summary: public category counts include verified reports only and suppress groups smaller than five. These historical counts are not live warnings; individual reports, targets, and summaries are never published.
- Honest uncertainty: there is no external live threat-intelligence integration; when local rules find no strong signal and no staged local feed match, the result is **Unable to determine**, never “safe”.
- Private reports: submissions start pending, are not exposed publicly, and can be checked using a random private reference.
- Private report appeals: after a decision, a reporter can request reassessment using their private reference. Only one appeal can be pending per report; accepting an appeal puts the report back into the pending review queue.
- Reviewer dashboard: the unlisted `/admin` page provides named sign-in, report totals, status/category/language and assignment filters, search, pagination, configured-reviewer assignment, bounded bulk actions, appeal review, feedback review, private case notes/handoffs, decision templates, reviewer workload/queue-age signals, operational status and recent action history. Reviewers can only see and act on reports assigned to their account. Session tokens remain in page memory and expire; moderation actions require a reason.
- Private clarification loop: reviewers can request non-sensitive additional details; reporters can read and answer requests only with their private report reference. Replies remain private and are visible to assigned reviewers. Report deletion and retention cleanup remove clarification records too.
- Threat-feed administration: administrators can stage validated JSON feeds, review version status, activate a staged version, and roll back to a previously activated version. Data is pasted into the local server; it never fetches a feed URL. Feed freshness, domain syntax, entry count, and a 1.5 MB upload cap are enforced.
- Protected audit export and session revocation: admins can download recent moderation history as CSV (spreadsheet formula prefixes are neutralized) and revoke all sessions for a named reviewer account.
- Duplicate report hints: exact category/target matches are flagged privately to reviewers; reports are never automatically merged or published.
- Result correction: users can send private feedback. The raw checked input is hashed before storage; only the user's optional feedback explanation is retained, so users are warned not to paste sensitive material into it. A random private reference lets the user check whether feedback remains pending or has been reviewed; no reviewer notes are exposed.
- Evidence notes: report submissions support optional, length-limited text notes; binary uploads are not accepted or stored.
- Local screenshot/QR helper: supported browsers can decode QR codes and experimental local text recognition on-device. Images are limited to 5 MB, never uploaded, and extracted links are never opened. If the browser lacks the APIs, checking is unavailable with an explanation.
- Optional threat-list matching: set `SCAMSHIELD_THREAT_FEED` to a local JSON threat-feed file. Feed format and freshness rules are documented below. No URL or message is sent to a third party.
- Local scam pattern library: bilingual English/Bangla user guides cover OTP/code theft, job-fee requests, payment pressure, link checks, prizes and recovery steps.
- Privacy/operations: users can delete reports and related appeal/audit/case-note/clarification records using their private reference. Startup cleanup removes reports and feedback older than `SCAMSHIELD_REPORT_RETENTION_DAYS` (default 365; bounded to 1–3650); scheduled cleanup repeats daily. Admin operations display database size, queue age and retention; configure `SCAMSHIELD_QUEUE_ALERT_HOURS` (default 72) for queue-age alerts. Alerts currently display in the authenticated dashboard; no external alert or email provider is configured. `/api/health` reports database status, uptime and aggregate counts. Set `SCAMSHIELD_BACKUP_PATH` to enable automatic integrity-checked SQLite backups (default interval 24 hours; configurable from 1–720 hours with `SCAMSHIELD_BACKUP_INTERVAL_HOURS`).
- Evaluation: `tools\evaluate_rules.py` measures precision, recall and false-positive rate by input channel and language using a labeled CSV; see limitations before using any test corpus.
- Moderation: pending reports can be reviewed as verified, rejected or escalated with a recorded reason. Configure a named account using `SCAMSHIELD_REVIEWERS` as described above; credentials are PBKDF2-SHA256 hashes and sessions expire after 30 minutes. The legacy `SCAMSHIELD_ADMIN_TOKEN` remains available for migration only.
- Mobile-responsive, keyboard-usable interface, accessible live announcements, CSP/security headers, bounded request sizes and basic per-IP request throttling.

## API

- `GET /api/health`
- `POST /api/check/url` — `{"url":"https://example.org","locale":"en"}` (`locale` may be `en`, `es`, `fr`, `hi`, `ar`, or `bn`; defaults to English)
- `POST /api/check/message` — `{"text":"Suspicious message...","locale":"es"}` (same supported locales)
- `POST /api/check/email-headers` — `{"headers":"From: sender@example.org\\nReply-To: other@example.net"}`
- `POST /api/check/context` — `{"kind":"job","text":"..."}; kind is job, marketplace, or payment`
- `POST /api/check/organization` — `{"domain":"reportfraud.ftc.gov"}`
- `POST /api/check/checklist` — `{"scenario":"payment"}` (`payment`, `job`, `marketplace`, `account`)
- `GET /api/public/organizations` and `GET /api/public/trends` — directory and privacy-thresholded aggregates
- `POST /api/reports` — `{"category":"job","target":"example.org","summary":"...","contact_channel":"email","incident_date":"2026-10-12","locale":"en"}`
- `POST /api/reports/export` — `{"reference":"private-reference"}` (downloads report and appeal details; keep the reference private)
- `POST /api/reports/status` — `{"token":"private-reference"}`
- `POST /api/reports/appeals` — `{"reference":"private-reference","details":"..."}`
- `POST /api/reports/clarifications/reply` — `{"reference":"private-reference","clarification_id":"...","message":"..."}`; a matching open request must exist
- `POST /api/feedback` — private check feedback; only SHA-256 of the checked input is retained
- `POST /api/feedback/status` — returns only `pending` or `reviewed` when given the private feedback reference
- `POST /api/reports/delete` — permanently deletes a report and its appeal/audit rows when given its private reference
- `POST /api/admin/login` — username/password login from `SCAMSHIELD_REVIEWERS`; returns a 30-minute in-memory bearer session
- `GET /api/admin/overview` — report and pending-appeal counts; requires `Authorization: Bearer <SCAMSHIELD_ADMIN_TOKEN>`
- `GET /api/admin/reports?status=pending&limit=20&offset=0` — report page (`pending`, `verified`, `rejected`, `escalated`, or `all`); same authorization
- `GET /api/admin/reports?assigned_to=me&category=job&locale=en` — reviewer queue filters; reviewers are restricted to assigned reports
- `GET /api/admin/appeals`, `/api/admin/audit` and `/api/admin/feedback` — review queues and recent moderation history; same authorization
- `GET /api/admin/audit/export` — protected CSV export (up to 10,000 recent records)
- `POST /api/admin/clarifications` — request additional private report details; requires an assigned report for reviewer accounts
- `GET /api/admin/feed`, `POST /api/admin/feed/stage`, `PUT /api/admin/feed/activate` and `PUT /api/admin/feed/rollback` — administrator-only, local threat-feed lifecycle
- `GET /api/admin/sessions`, `POST /api/admin/sessions/revoke` — administrator-only named-session view and revocation
- `PATCH /api/admin/reports/assign` — administrator assigns a pending report to a configured reviewer
- `PUT /api/admin/reports/bulk` — administrator bulk review (maximum 50 reports with one required audit reason)
- `PATCH /api/admin/appeals/{id}` — same authorization; `{"status":"accepted","reason":"..."}` (`accepted` reopens the report)
- `PATCH /api/admin/feedback/{id}` — mark private user feedback reviewed
- `GET` / `PATCH /api/admin/reports/{id}/notes` — read or add private case notes and reviewer handoffs
- `GET /api/admin/operations` — queue-age, database-size, retention, and pending-feedback status for the dashboard
- `GET /api/admin/reports` — `Authorization: Bearer <SCAMSHIELD_ADMIN_TOKEN>`
- `PATCH /api/admin/reports/{id}` — same authorization; `{"status":"verified","reason":"..."}`

## Research translated into product decisions

The supplied competitor-research blueprint recommends a guest-first checker, URL and message inputs, explained evidence, cautious language, reporting and moderation before OCR or machine learning. Its desk research identifies different existing products across scam checking, threat feeds and reporting; it cautions that this is documentary comparison, not hands-on competitor testing. It also warns that some external APIs have non-commercial limits, quotas, or sharing restrictions. Accordingly, this MVP does not send submitted URLs/messages to third parties or claim live reputation results.

Primary references to re-check before adding integrations:

- [Google Safe Browsing API reference](https://developers.google.com/safe-browsing/reference) — API behavior, freshness and privacy details; verify current eligibility and use terms before a production integration.
- [OWASP SSRF Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html) — rationale for never fetching arbitrary user-provided links.
- [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) — relevant before adding screenshot/OCR upload.
- [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/) — accessibility target for the public interface.
- Google Safe Browsing, VirusTotal, urlscan.io, PhishTank and OpenPhish are not interchangeable drop-in services; terms, availability, disclosure behavior, attribution, licensing and quotas must be checked individually.

## Important limitations and next steps

Local URL feed format (`SCAMSHIELD_THREAT_FEED`) is a JSON object such as `{"provider":"Reviewed local list","updated_at":"2026-10-16T00:00:00+00:00","domains":["example.invalid"]}`. Only fresh (14-day) exact-host matches are used; invalid or stale feeds do not produce a threat match. This is a local-file integration, not an external provider connection; vet the source, licensing, freshness and any disclosure policy before adopting an online feed. Screenshot QR/OCR relies on browser APIs that are not consistently available; currently there is no server OCR, attachment storage, malware sandboxing, or guarantee of Bengali text recognition. Status email notifications remain intentionally unconfigured: no email address is collected and no SMTP provider has been selected or secured. Community trends are aggregate-only; per-report warning cards are not published because the current flow has no explicit public-sharing consent and anonymization review.

The local rules are demonstration heuristics, not an independently evaluated classifier and not a calibrated probability. A keyword match can be a false positive. There is no DNS lookup, URL content fetch, CAPTCHA, email/SMS block, or external provider connection. Named admin accounts use salted PBKDF2 hashes, optional TOTP MFA, persisted login throttling, and admin-triggered session revocation; this standard-library pilot still needs HTTPS termination, production-grade deployment and monitoring before internet exposure. The legacy static token is a migration path and has no MFA. Retention deletion runs at startup and daily thereafter. Backups must be stored securely because the SQLite database contains private reports; configure an off-host protected backup location in production and test restores. Before public deployment, conduct formal privacy/security review, legal review, evaluate a representative holdout corpus by language, and verify accessibility with assistive technologies.

### Readiness review (2026-10-16)

- **Privacy notice:** `/privacy.html` is an English-only, noindex pre-launch draft based on the current code. The operator reports that Fatima Abid is their full legal name, operates as an individual in Pakistan, and intends a general audience that may include minors. A public privacy contact is not set up; exact service regions, hosting configuration, rights process, and legal review remain unresolved. The operator's goal is global availability, but the current 11 directory links do not define service coverage. Complete these details and obtain jurisdiction-specific and child-safety/privacy review before launch; do not represent the draft as a final notice.
- **Privacy strengths:** pasted checks are analyzed without retaining the submitted text or sending it to an external provider; browser history stores result summaries on the user's device; reports are private, have a private-reference deletion route, and are removed after the configured retention period (365 days by default). The contact field records only a preferred contact method; no email address or phone number is collected.
- **Privacy work before launch:** reports and reviewer notes may contain sensitive information and are stored in SQLite without application-level encryption. The feedback queue stores a SHA-256 digest of checked input; hashes can still be matched against guesses and must not be described as anonymous. The per-IP rate limiter keeps client addresses in process memory until restart. Deleting a report from the live database does not erase copies already present in backups. Restrict database/backup access, encrypt storage and backups, reduce/expire in-memory IP state, and define backup expiry/deletion handling with the operator.
- **Security/deployment work before launch:** the built-in server is intended for loopback use, not direct internet exposure. Put it behind a maintained HTTPS reverse proxy, configure HSTS there, protect and rotate backups, monitor service/queue health, and disable the legacy static-token path in favor of named accounts with MFA. The in-process request throttle is not a substitute for edge rate limiting in a multi-process deployment. This review is a code/documentation readiness pass, not a penetration test.
- **Name and trademark review:** the former working name, ScamShield, is also used by Singapore's public ScamShield service ([official site](https://www.scamshield.gov.sg/)); this project is not affiliated with it. The project uses **ClearBeacon** as a provisional display name only. A basic exact-phrase web search returned no results for ClearBeacon, but this is not trademark clearance; the [WIPO Global Brand Database](https://branddb.wipo.int/) blocked automated lookup behind interactive verification, and no comprehensive national-register search was performed. The `.com`, `.net`, and `.org` domains are registered according to [Verisign `.com` RDAP](https://rdap.verisign.com/com/v1/domain/clearbeacon.com), [Verisign `.net` RDAP](https://rdap.verisign.com/net/v1/domain/clearbeacon.net), and [PIR `.org` RDAP](https://rdap.publicinterestregistry.org/rdap/domain/clearbeacon.org); none is available as a new registration. Other TLDs have not been confirmed. The proposed alternative CheckHarbor was rejected after finding an active [CheckHarbor site](https://checkharbor.com/) advertising email, phone, and IP risk APIs. No comprehensive trademark clearance has been completed for the 11 linked regions or any other territory. Do not publicly launch as ClearBeacon until qualified counsel completes relevant clearance and a usable domain is secured.
- **Legal review:** no legal conclusion or jurisdictional compliance claim is made here. An operator must identify where the service and its users are located, determine applicable privacy/consumer/reporting obligations, and have qualified local counsel review the notice, retention, reporting workflow, and name before launch.
- **Accessibility:** targeted browser checks covered document landmarks, accessible names for rendered controls and links, heading names, duplicate IDs, image alternatives, keyboard focus, and horizontal overflow at 320–1280px. Earlier checks found and fixed a missing label on the reviewer bulk-action reason field. A subsequent keyboard review found that the URL/message ARIA tablist lacked arrow-key navigation; it now supports Left/Right and Home/End with roving tab stops and RTL-aware arrows. Measured color review found low-contrast accent text and guide arrows; the accent, arrows, placeholders, and focus-ring color were darkened. Local browser checks are not an independent audit or a WCAG conformance assessment. Screen-reader workflows, browser/OS combinations, forced-colors, magnification/reflow, all interactive states, authenticated dashboard views, and WCAG 2.2 AA still require independent specialist/assistive-technology validation.
- **Planned hosting:** the operator intends Vercel hosting and has selected Supabase Postgres as the planned persistent database, but neither is configured or deployed. Current Vercel documentation supports Python ASGI/WSGI functions; this project currently runs a custom `ThreadingHTTPServer`, persists reports in SQLite, and keeps reviewer sessions/rate-limit state in process memory. It is not deployment-ready as-is. Convert the app to a supported request handler, migrate data to Supabase Postgres, move session/rate-limit state to an appropriate shared store, choose and verify compatible function and database regions, and review Vercel/Supabase logging, subprocessors, retention, backups, and transfer terms before updating the privacy notice. Vercel documents `iad1` (Washington, D.C., USA) as the default region for new function projects unless changed. An international CDN does not mean functions or personal data are processed in every user's country. Sources: [Vercel Python runtime](https://vercel.com/docs/functions/runtimes/python), [function regions](https://vercel.com/docs/functions/configuring-functions/region), [Vercel storage](https://vercel.com/docs/storage), and [Supabase regions](https://supabase.com/docs/guides/platform/regions).

For evaluation, prepare a UTF-8 CSV with `type,input,locale,expected` columns (`type` is `url` or `message`; `expected` is `scam` or `benign`) and run `python tools\evaluate_rules.py path\to\labeled.csv`. The script treats only `high_risk`/`known_malicious` as positive; `caution` remains an uncertain state and must be reviewed separately. Do not put personal data in evaluation files. `tools\synthetic_rule_evaluation.csv` is a 36-row synthetic smoke-test corpus across all supported locales and input types, not a representative or independently labeled holdout set; its metrics cannot establish real-world accuracy. On this toy set, all six URL archetypes remained below the positive threshold (0/6 recall), and French messages had one miss in two positive examples; the other message locales detected both examples. These results are diagnostic only.

Candidate public URL dataset: [UCI PhiUSIIL Phishing URL Dataset](https://archive.ics.uci.edu/dataset/967/phiusiil+phishing+url+dataset) exposes a raw URL column and binary phishing/legitimate target and could support an offline URL-only evaluation, without opening or resolving any row. UCI reports 235,795 rows (100,945 phishing and 134,850 legitimate); its metadata lists target column `label`, while the author's [Kaggle metadata](https://www.kaggle.com/api/v1/datasets/metadata/ndarvind/phiusiil-phishing-url-dataset) maps `0` to phishing and `1` to legitimate. UCI lists CC BY 4.0 while the author's metadata lists CC BY-NC-SA 4.0. That license discrepancy is unresolved; do not download/use it for project evaluation or product claims until permission/terms are confirmed with the rights holder. A Hugging Face dataset candidate declares CC BY-SA 4.0 in its card metadata, but the card supplies no source/provenance or attribution details; the declaration alone is insufficient to establish the uploader's rights, so it was not adopted or downloaded. The operator states the project is strictly non-profit educational/research use, which may fit [URLhaus Community API](https://urlhaus.abuse.ch/api/) free authenticated [fair-use terms](https://abuse.ch/terms-of-use/#principles), subject to provider approval, authentication, and limits. URLhaus is a time-sensitive malware URL feed, not a balanced phishing/benign dataset, and cannot alone support full accuracy metrics. [Tranco](https://tranco-list.eu/) offers popularity rankings for research and reproducible snapshots, but the reviewed public page did not supply a clear dataset reuse license; popular-domain membership also is not proof a URL is benign. A Zenodo malicious-URL software record declares `other-open`, not a standard license ([record 2544082](https://zenodo.org/records/2544082)). No candidate reviewed so far provides both sufficiently clear reuse rights and a suitable, independently labeled raw-URL holdout set; nothing has been downloaded or used. No verified, rights-cleared single message corpus exists for all six supported locales. A representative multilingual evaluation still requires a licensed, consented/de-identified holdout set and domain-expert labeling by language/channel.

Create and validate a consistent SQLite backup with `python tools\backup_database.py data\scamshield.sqlite3 backups\scamshield-copy.sqlite3`. Restore drills should only be performed against a separate copy and an agreed maintenance window.
